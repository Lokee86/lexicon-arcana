# Lexicon Rust migration

Parent index: [Lexicon Documentation](README.md)

## Purpose

Define the active parity-first migration boundary from the Go Lexicon application to the Rust `lexicon` library and its Rust-owned toolchain surfaces.

## Overview

The migration keeps the existing Go implementation as the behavioral reference until each Rust slice reaches its applicable parity gate. Versioned contracts under `spec/` remain authoritative; migration fixtures are verification evidence, not new product contracts.

The Rust implementation is not yet the recommended operator runtime because optimization work remains incomplete. Until that performance gap is closed, user-facing documentation should direct normal users to the last optimized Go reference revision, `758af9daf6e71fc0a7ebb837875efe366f6403fd`.

## Current migration boundary

The existing Go implementation remains the behavioral parity oracle during migration. The Rust `lexicon` library and separate `lexicon-cli` crate now own the replacement executable surface.

The reference implementation is pinned at commit
`758af9daf6e71fc0a7ebb837875efe366f6403fd`. Migration fixtures and the general differential harness live under
`evaluation/rust_migration/`. The completed Go-language adapter migration retains immutable fixture repositories under `testdata/go_oracle/repositories/` and canonical facts under `testdata/go_oracle/golden/`; its retained Demon Docs and Space Rocks calibration revisions are documented with that oracle evidence.

## Completed foundation

The migration foundation and Interstack synthesis slice are implemented:

- the Go parity oracle is pinned and representative contract, snapshot, incremental, recovery, and full-scan migration vectors are recorded;
- the private `adapters/go-semantic/` helper exposes the version-2 semantic-observation protocol for the native Go adapter. The protocol accepts a canonical repository root, eligible `.go`/`go.mod` inventory, optional module roots, and worker/shard/fan-in parameters; it returns typed declaration, relationship, callsite, capture, dataflow, and diagnostic observations using helper-local semantic keys and compiler evidence rather than Lexicon SHA IDs or final Lexicon policy. Strict helper/Rust decoding tests reject unsupported versions, malformed paths, unknown fields or record kinds, invalid semantic identities, and incomplete spans;
- Rust now has a native `GoAdapter` registered by `AdapterHost` plus the semantic-free shared `FrontendRunner`. The runner performs deterministic executable/argument/environment construction, framed stdin/stdout transport, bounded stderr capture, exit-status reporting, protocol-version handshake validation, and child termination/reaping on malformed responses; Go-specific protocol and semantic policy remain in the Go adapter. The Go adapter fingerprint includes both Rust-side sources and the helper version;
- Rust now owns Go repository discovery and module ownership. The native adapter preserves the legacy permanent exclusions, records every visible directory without following directory symlinks, inventories only `.go` and `go.mod`, parses all module roots, assigns each input to its nearest module, preserves root-module versus multi-module repository identity, and passes only the Rust-owned sorted file/module inventory to the helper. Repository, directory, and file nodes and containment edges are now emitted directly in Rust with legacy-compatible IDs and content hashes. All seven frozen Go fixtures verify exact repository-structure parity;
- the structural Go AST layer is now extracted into `adapters/go-semantic/` rather than rewritten. The helper uses the Rust-supplied inventory and standard `go/parser`/AST traversal to report canonical package, import, named-type, function, method, test, interface-method, and closure declarations with owner/span/container metadata. It has no Lexicon `NodeKey`, SHA hashing, facts-v1 emission, repository crawler, or persistence ownership. Rust materializes those declarations into nodes and `contains`/`defines`/`imports` relationships. The seven frozen fixtures, including inactive build-tag variants, match the legacy declaration slice exactly;
- Rust now owns canonical Go graph identity in `src/adapters/go/identities.rs`. Repository/file/package/type/callable/interface-method/closure/capture/SSA/builtin/type-expression and other legacy identity forms share one prefix-to-Lexicon-kind mapping before SHA generation; helper identities are validated against the declared fact kind, absolute path material is rejected, and internal `_test` namespaces follow the legacy canonicalization rule. Legacy identity vectors and all seven permanent fixtures preserve the old node SHA IDs;
- the private Go helper now owns the extracted `go/packages` / `go/types` index used by later semantic phases. It preserves `packages.LoadAllSyntax | packages.NeedModule`, test-enabled loading, deterministic package flattening, generic function origins, `types.Unalias`, internal `_test` namespace canonicalization, completed interfaces, and distinct value/pointer method sets while restricting repository-local targets to the Rust-supplied inventory. Package/type-check failures are transported as structured diagnostics and are not materialized as facts;
- typed Go relationships now flow through that helper index as canonical semantic endpoint identities: embedded named types and embedded interfaces emit `extends`, repository-local interface satisfaction emits type- and method-level `implements`, and embedded method replacement emits `overrides`. Rust validates both endpoint identities, materializes legacy ownerless namespace/type contracts for external or standard-library embedded targets, rejects `implements` self-edges, and preserves the legacy owner-scoped/spanless fact shape. The seven permanent fixtures preserve exact relationship parity;
- typed direct-call resolution is now extracted into the helper from the legacy `semantic_calls.go` path. The helper reports caller/target semantic identities, normalized callsite spans, explicit `internal`/`external`/`builtin`/`conversion`/`dynamic`/`interface` classification, and unresolved reason/candidate information. Rust materializes external/builtin/type contracts and converts observations into `calls`, `possible-calls`, `converts-to`, or unresolved facts. Direct internal/cross-package calls, methods, concrete receivers, recursion, builtins, external/stdlib functions, conversions, and dynamic unresolved expressions preserve the legacy behavior; the frozen `basic_calls` fixture has exact call-edge/unresolved parity;
- repository-wide Go SSA/VTA reconciliation is now extracted into the helper without algorithmic redesign. It preserves `ssautil.AllPackages(..., ssa.InstantiateGenerics)`, VTA callgraph construction, function-variable and callback flow, returned functions, method values, interface invokes, closure call targets, and synthetic compiler function identities. SSA outcomes merge into the existing caller+callsite observations using the legacy rule: non-interface resolved direct calls remain authoritative, concrete interface targets replace contract targets, one target emits `calls`, and multiple targets emit `possible-calls`. Active typed fixtures preserve exact call-target parity; the inactive `build_tags` fixture remains outside the SSA gate because `go/packages` does not load its `special` build variant;
- closure capture semantics now cross the helper boundary from the same SSA authority. Structural closure declarations remain AST-owned, including nested immediate-parent containment, while `ssa.Function.FreeVars` reports free-variable capture evidence. Positioned captures preserve their canonical positioned-variable identity and point-span `references` evidence; Rust recreates the final legacy identifier-width variable node. Positionless captures carry only slot/name evidence, and Rust derives the exact legacy `capture:<closure-node-id>:<index>:<name>` identity. Permanent-fixture capture nodes/edges and closure call relationships match the oracle exactly;

## Parity rule

Migration work preserves the versioned contracts under `spec/`. A behavior mismatch is fixed against the Go reference before it is accepted in Rust unless a separate compatibility migration is explicitly approved.

Durable byte contracts require byte equality. Behavioral slices use the narrowest deterministic observable comparison available. For the completed Go-language adapter migration, immutable frozen goldens now protect compatibility without retaining a second executable facts implementation. Other migration slices may retain legacy implementations only while those implementations still own untranslated behavior or are required as explicit oracles.

## Verification

Run the Rust foundation checks from `lexicon/`:

```text
cargo fmt -- --check
cargo test
cargo clippy --all-targets -- -D warnings
```

Run the migration comparator against a candidate fixture directory with:

```text
python evaluation/rust_migration/compare.py PATH
```

The existing Go tests remain required while they own untranslated behavior.

## Go adapter migration completion

Go adapter Phases 0–19 are complete. Go-language analysis is owned by the native Rust `GoAdapter` plus its private packaged `go-semantic` helper, with immutable compatibility evidence under `testdata/go_oracle/` and no live standalone Go facts implementation. Future Go work is ordinary adapter maintenance or optimization. The broader Lexicon migration and its operator-runtime recommendation remain governed by this document and [Status](STATUS.md); other language-adapter migrations continue independently.
