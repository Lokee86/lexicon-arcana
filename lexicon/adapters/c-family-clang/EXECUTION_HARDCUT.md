## Result envelope and module boundary

The private complete-TU envelope is:

```text
CompleteTUResult {
  phase: Real | Synthetic | Orphan
  rank: size_t                 // phase-local canonical plan index
  frontend_status: int         // includes driver skip/rejection
  observations: State          // complete move-owned TU state
}
```

`State` is the existing `structural_model.h` type, not the public file
frame. A store round-trip must preserve its repository root; complete file
map (declarations, macros, includes, relationships, calls, bindings, accesses,
diagnostics and declaration identity sets); active/all owned and suppressed
path sets; context identities; translation units (directory, command, language,
synthetic flag); global diagnostics; and semantic-analysis nanoseconds.
Preserve the frontend status in the envelope, not inside the file payload.

The **scheduler** assigns phase-local ranks; **workers** parse and relinquish
compiler state, reclaim, then hand off complete envelopes. The **store**
retains or streams results to request-local spill files without claiming
files. The **single committer** waits for canonical rank, applies existing
claim/coverage/context-identity rules, and emits claimed file states through
the unchanged transport. Rust remains the canonical ID/fact policy owner.

Real results must drain and establish valid real coverage before selecting
synthetic units. Prior-phase suppression is immutable throughout a phase.
Orphan fallback owns only still-unclaimed header paths. Every planned rank
must terminate, including a driver-skipped input. Phase completion and valid
success require all ranks to drain and all writes to succeed.

## Accounting and initial internal limits

| Resource | Proposed Step 3 policy | Counting boundary |
| --- | --- | --- |
| Completed resident results | 64 MiB | `estimated_retained_bytes(State)` at store admission; release on pop or successful spill |
| Descriptors | One per admitted/completed rank | Count separately; no arbitrary 8-result window |
| Request-local spill | 2 GiB initial finite quota | Actual committed spill-file bytes, never an estimate |
| Direct frontier | One slot | Next canonical rank bypasses normal queue and disk quotas |
| Active Clang memory | Phase-5 measured admission budget | Derive from process-tree target after explicit reservations |

The 64 MiB retained estimate includes container/vector capacities and
dynamic strings but is **not** an RSS cap. The estimate excludes active ASTs,
the producer's result during handoff, frontier decoding, transport encoding,
Rust baseline and allocator-retained pages. Report these separately. The
2 GiB spill policy is an initial, internal design choice subject to targeted
quota/oversize tests, not a public protocol option.

On pressure, suspend future-rank dispatch, finish admitted parses and
frontier delivery, drain ranks and release storage, then resume. An oversized
future result cannot wait forever for an impossible quota: it must reach the
reserved frontier path or produce an explicit resource-limit failure.
Use a private versioned streaming codec with checked record lengths and
complete-record validation; do not reuse incomplete public file frames.

Limits used to force spill, corruption, read/write failure and cancellation
in tests belong on the **internal store constructor**, not in the helper
request. No migration-only façade or second ownership path is permitted.



## Step 2: teardown, reclamation and telemetry (implementation)

Reclamation is now invoked in the worker's completed-result callback after
`FrontendActionFactory::runInvocation` destroys compiler/AST state **and before**
`OrderedObservationCommitter::submit` can block. The policy retains its
serialized nonblocking try-lock, 64 MiB free-chunk threshold and resident-growth
guard. The previous unconditional post-handoff placement was removed. Driver
failures that do not invoke an action produce terminal results and reach the
same pre-handoff reclamation point after the ClangTool run.

With `LEXICON_PERF=1`, records are constructed as complete lines under a
shared output mutex and TU records carry the phase (`real`, `synthetic`,
`orphan`) and phase-local rank. Existing `tu.before_parse`, `tu.parsed`,
`tu.visited`, `tu.after_teardown` and `tu.after_submit` markers remain.
The additional `c-family.clang.teardown` marker measures traversal-completion
to post-compiler-destruction; when no traversal occurred, `measured=0` prevents
inventing a teardown duration. `heap_reclaim` distinguishes policy invocations
from actual trim attempts/successes. New ordered-admission, result-handoff,
file-encoding, transport-lock-wait and file-write events separate waiting from
work; none of these events changes canonical output.

The full calibration log for each cold, warm or worker-count run is persisted
under the case's results `logs/` directory, not inside a disposable fixture.
The result record contains `perf_log` for the exact retained file. Aggregation
sums counters/durations, takes maximum observed gauges and excludes phase/rank
from aggregate records; phase/rank remain in full logs. Active AST reservations,
shared scheduler dispatch waits, spill bytes and frontier decoding only become
measurable once the corresponding Step 3/5 mechanisms exist; the current
ordered-admission wait is explicitly **not** a future scheduler admission metric.

Correctness gates include the pinned 1/2/4-worker golden, native heap/profiling
tests and parser/log-persistence regression. No full CBM run is part of Step 2.
